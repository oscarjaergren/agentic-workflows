# REVIEW.md

What matters when reviewing this repository. The AI reviewers read this on
every pull request; edit it when the same review comment keeps coming up.

## What failure looks like here

- **Workflows** (`.github/workflows/*.md`): the frontmatter grants more than
  the prompt needs, a safe output can write somewhere it should not, or the
  prompt tells the agent to do something the safe outputs do not allow.
- **Prompts:** an instruction contradicts the shared review rules, or a step
  asks for evidence the agent has no way to get.
- **Scripts** (`scripts/`): a failed command is silently ignored, or a token
  could end up in output.
- **Docs:** the README or a checklist describes behaviour the workflows no
  longer have. It lies.

## Skip

- `*.lock.yml` and `.github/aw/`: generated by `gh aw compile`. Review the
  `.md` source instead, and flag a pull request that changes a lock file
  without its source.

## Risk tiers

The change sets the tier, not the author.

- **Low:** docs, comments and checklist wording. The AI reviewer may approve
  these on its own.
- **Medium:** prompts, `REVIEW.md` and scripts. Needs one human approval.
  `REVIEW.md` steers the reviewer, so the reviewer never approves its own
  instructions.
- **High:** workflow frontmatter (permissions, triggers, safe outputs,
  engine, secrets) and anything under `.github/` that is not a prompt. Needs
  one human approval, and the reviewer never approves.
